# Idol Store 🛍️

استور شخصی اپلیکیشن‌های اندروید، شبیه گوگل‌پلی اما برای اپ‌هایی که **خودت** معرفی می‌کنی.
برای هر اپ فقط **آدرس صفحه ریلیز گیت‌هاب** را می‌دهی؛ اپ خودش هر بار که ریلیز پایدار جدید منتشر شود،
فایل **APK یونیورسال** را پیدا و برای دانلود مستقیم در دسترس کاربر می‌گذارد.

- 🔐 **ورود با حساب گیت‌هاب** برای استفاده از اپ (کد دستگاه OAuth یا توکن شخصی)
- ⭐ **ستاره‌دادن به پروژه‌ها از داخل اپ**
- 🤖 خود اپ هم متن‌باز است و با **GitHub Actions** روی گیت‌هاب ساخته و منتشر می‌شود

## اعلان بروزرسانی (اختیاری برای هر اپ) 🔔

- در صفحه هر اپ، کارت «اعلان بروزرسانی» با **سوییچ** هست: کاربر خودش برای هر اپ جداگانه تصمیم می‌گیرد روشن باشد یا نه.
- وقتی روشن باشد، اپ در پس‌زمینه (هر ۶ ساعت با WorkManager) نسخه‌های آن ریپو را چک می‌کند؛ به محض انتشار ریلیز پایدار جدید، اعلان می‌آید: «بروزرسانی X — نسخه v1.2 منتشر شد».
- **کلیک روی اعلان → باز شدن مستقیم صفحه همان اپ** در استور؛ نصب یا نه را خود کاربر تصمیم می‌گیرد.
- روی اندروید ۱۳+ مجوز POST_NOTIFICATIONS هنگام فعال‌کردن سوییچ گرفته می‌شود.

## چیدمان استور (شبیه گوگل‌پلی) 🧩

- **نوار پایین:** استور / جستجو / دسته‌ها / شما
- **استور:** نوار چیپ‌های دسته‌بندی بالای صفحه (مثل Top charts / Categories در پلی) + سکشن‌های عمودی:
  - «بروزرسانی‌های اخیر» (جدیدترین ریلیزهای پایدار)
  - یک سکشن برای هر دسته با ۴ ردیف بزرگ (آیکون + نام + توضیح دوخطی + نسخه) و دکمه «مشاهده همه»
- **جستجو:** سرچ فول‌اسکرین روی نام/توسعه‌دهنده/دسته
- **دسته‌ها:** لیست دسته‌ها با تعداد اپ — با کلیک، فهرست کامل آن دسته
- **شما:** حساب کاربری + فهرست اپ‌های نصب‌شده روی دستگاه + خروج
- **صفحه اختصاصی هر پروژه:** آیکون، نام، توضیحات (از کاتالوگ یا خود ریپو)، اطلاعات تماس سازنده (وب‌سایت/ایمیل/گیت‌هاب/تلگرام — کلیک‌خور)، نسخه و تاریخ آخرین ریلیز پایدار، تغییرات، ریلیزهای قدیمی‌تر، ستاره‌دادن و سوییچ اعلان.

## دسته‌بندی‌ها 🗂️

ادمین در پنل مدیریت، فیلد «دسته‌بندی‌ها» را با کاما ویرایش می‌کند (مثلاً: ابزارها، رسانه، امنیت و حریم خصوصی) و هر اپ در فرم خودش یک دسته می‌گیرد. چیپ‌های صفحه استور، سکشن‌ها و تب دسته‌ها همه از همین لیست تغذیه می‌شوند.

## پنل مدیریت 🔒

### کجاست و چطور وارد می‌شوم؟
پنل مدیریت **داخل خود اپ** است. در نوار بالای صفحه اصلی استور، آیکون 🛡️ (تنها برای مدیران دیده می‌شود) → صفحه «پنل مدیریت».
در آن می‌توانی اپ اضافه/ویرایش/حذف کنی، لیست مدیران را عوض کنی و با دکمه **«انتشار در گیت‌هاب»** تغییرات به‌صورت یک کامیت واقعی در ریپوی کاتالوگ (apps.json) ذخیره می‌شود — تاریخ‌دار و با نام کاربری خودت.

### چه کسی می‌تواند وارد شود؟
فقط نام‌های کاربری گیت‌هابی که در فیلد `admins` کاتالوگ هستند (و در بوت‌استرپ اولیه: مالک ریپوی کاتالوگ):

```json
{
  "admins": ["Alvandcode", "friend1"],
  "apps": [ ... ]
}
```

برای اعطای دسترسی، نام کاربری را به `admins` اضافه کن (از خود پنل یا با ویرایش apps.json) و منتشر کن. برای سلب دسترسی فقط کافی است از لیست حذفش کنی — توکن او بلافاصله بی‌اثر می‌شود.

### آیا هکر می‌تواند وارد شود؟ سه لایه حفاظت:
1. **UI قفل است:** پنل فقط برای حساب‌های داخل `admins` رندر می‌شود؛ بقیه اصلاً آیکون آن را نمی‌بینند و اگر مسیر را جعل کنند، پیام «دسترسی ندارید» می‌گیرند.
2. **حفاظ واقعی، گیت‌هاب است:** هر تغییر = یک کامیت در ریپوی کاتالوگ با GitHub API. گیت‌هاب فقط به توکنِ حساب‌هایی که دسترسی push به آن ریپو دارند اجازه نوشتن می‌دهد — این را هیچ‌کد و هیچ‌UI نمی‌تواند دور بزند. حتی اگر هزار بار UI را جعل کنند، بدون توکنِ مجاز، پاسخ گیت‌هاب 403 است.
3. **زیرساخت امن:** توکن‌ها فقط با HTTPS منتقل و با AES-256 (`EncryptedSharedPreferences`) روی دستگاه ذخیره می‌شوند؛ هیچ سرور واسط و هیچ secret داخل کد وجود ندارد (Client ID عمومی و بی‌خطر است).

### راه‌اندازی پنل
در `app/build.gradle.kts` این دو را با مقادیر خودت تنظیم کن:

```kotlin
buildConfigField("String", "CATALOG_REPO", "\"USERNAME/idol-store-catalog\"")
buildConfigField("String", "CATALOG_PATH", "\"apps.json\"")
```

نکته: توکن کاربرِ مدیر باید دسترسی push به ریپوی کاتالوگ داشته باشد (OAuth App با scope `public_repo`، یا PAT کلاسیک). تغییرات raw گیت‌هاب ممکن است تا ۵ دقیقه کش‌شده باشد.

## نحوه کار

1. کاربر با حساب گیت‌هاب وارد می‌شود (لازم است چون GitHub API بدون ورود، سهمیه‌ی نرخ بسیار کمی دارد و ستاره‌دادن هم توکن می‌خواهد).
2. اپ فایل `apps.json` را از آدرس `BuildConfig.CATALOG_URL` می‌خواند.
3. برای هر اپ، از GitHub API ریلیزهای ریپو را می‌گیرد، **draft و prerelease را کنار می‌گذارد** و آخرین ریلیز پایدار را برمی‌دارد.
4. از بین asset ها، APK یونیورسال را تشخیص می‌دهد (اولویت: اسم دارای `universal` > اسم بدون `arm64/armeabi/x86`).
5. دانلود با درصد پیشرفت → دکمه «نصب» → درخواست مجوز منابع ناشناس در صورت نیاز.
6. دکمه ستاره در صفحه اپ، پروژه را برای حساب کاربر ستاره می‌کند / برمی‌دارد.

## راه‌اندازی (۴ قدم)

### ۱. این ریپو را در گیت‌هاب منتشر کن
هر پوش به `main` → Actions یک APK می‌سازد (Artifact). برای انتشار رسمی:

```bash
git tag v1.0.0
git push origin v1.0.0
```

APK به **Releases** پیوست می‌شود. خود Idol Store هم می‌تواند در کاتالوگ ثبت شود تا کاربرانش آن را از داخل استور آپدیت کنند.

### ۲. ریپوی کاتالوگ + آدرس آن
یک ریپوی جدا (مثلاً `idol-store-catalog`) بساز، `apps.json` و پوشه `icons/` را داخلش بگذار، و در `app/build.gradle.kts`:

```kotlin
buildConfigField("String", "CATALOG_URL",
    "\"https://raw.githubusercontent.com/USERNAME/idol-store-catalog/main/apps.json\"")
```

### ۳. اپ‌ها را به کاتالوگ اضافه کن
دیگر لینک APK لازم نیست! فقط ریپو یا صفحه ریلیز را بده:

```json
{
  "id": "org.example.app",
  "name": "نام اپ",
  "developer": "توسعه‌دهنده",
  "category": "دسته",
  "description": "توضیحات",
  "iconUrl": "https://raw.githubusercontent.com/.../icons/app.png",
  "packageName": "org.example.app",
  "github": "owner/repo"
}
```

قبول است: `owner/repo`، `https://github.com/owner/repo`، `https://github.com/owner/repo/releases` یا `.../releases/latest`.

**شرط‌ها:**
- ریلیز باید **پایدار** باشد (تیک prerelease و draft نخورده باشد).
- در asset های ریلیز باید یک APK با اسم یونیورسال باشد (مثلاً `app-universal-release.apk`) یا APK ای که اسمش معماری ندارد. برای پروژه‌های gradle راه‌حل رایج: build variant `universalRelease`.
- `packageName` را بده تا اپ بفهمد چه نسخه‌ای نصب است و برچسب «نصب‌شده» بزند.

### ۴. ورود کاربران با گیت‌هاب
دو راه (هر دو در اپ هست):

**الف) کد دستگاه (پیشنهادی — تجربه واقعی «Sign in with GitHub»):**
1. در `github.com/settings/developers` یک **OAuth App** بساز (Homepage هرچه می‌خواهی، Callback URL = `http://localhost`).
2. Client ID را در `app/build.gradle.kts` بگذار:
```kotlin
buildConfigField("String", "GITHUB_CLIENT_ID", "\"Iv1.xxxxxxxxxxxx\"")
```
3. کاربر کد یک‌بارمصرف را در `github.com/login/device` وارد می‌کند — تمام.

**ب) توکن شخصی (PAT):** کاربر از `github.com/settings/tokens` یک توکن **Classic** با دسترسی `public_repo` می‌سازد و داخل اپ وارد می‌کند.

توکن با `EncryptedSharedPreferences` (AES-256) ذخیره می‌شود و در آیکون خروج (⏻) نوار بالای استور پاک می‌شود.

## بروزرسانی خودکار استور

خود Idol Store را هم داخل کاتالوگ ثبت کن (`github` = آدرس همین ریپو). هر تگ جدید → ریلیز پایدار جدید → کاربران از داخل استور آپدیت می‌کنند.

## ملاحظات

- مجوز `REQUEST_INSTALL_PACKAGES` یعنی گوگل‌پلی این اپ را نمی‌پذیرد — طبیعی است؛ توزیع از گیت‌هاب است.
- `versionCode`/`versionName` استور در `app/build.gradle.kts` است؛ هر انتشار: بروزرسانی + تگ.
- ستاره‌دادن نیازمند توکن با اجازه ستاره است (OAuth App با scope پیش‌فرض اپ، یا PAT کلاسیک).
